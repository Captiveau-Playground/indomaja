# GitHub Copilot Instructions - Indomaja Project

You are an expert Full-stack Developer and SEO Strategist working on the Indomaja project. Follow these strict coding specifications.

**Current Scope**: Static Website with JSON-LD data integration and Extreme SEO Performance.

## 1. SEO-First & Static-First Implementation

### a. Static Site Generation (SSG)

- Prioritize Server Components (RSC) for all pages
- Ensure all pages are statically generated for peak performance and crawlability
- Use `next/image` with priority for above-the-fold content

### b. Proper Heading Hierarchy

- Only ONE `<h1>` per page, representing the main topic
- Use `<h2>` to `<h6>` in strict nested hierarchy without skipping levels
- Ensure headings are descriptive and include relevant keywords

### c. Metadata Management

- Use Next.js `Metadata` API in `layout.tsx` (global) and `page.tsx` (page-specific)
- Every page MUST have a unique `title` (max 60 chars) and `description` (max 160 chars)
- Implement OpenGraph (`og:title`, `og:description`, `og:image`) and Twitter card tags

### d. URL Structure

- Maintain flat and clean URL structure (e.g., `indomaja.co/services/digital-marketing`)
- Use lowercase and hyphens for slugs

## 2. Structured Data (JSON-LD)

- Implement JSON-LD using `<script type="application/ld+json">` tag
- **Organization Schema**: Included globally (usually in root layout)
- **Website Schema**: Include search action if applicable
- **Service/Product Schema**: Implement on specific service/detail pages

## 3. Analytics Setup

### a. Integrations

- **Google Analytics 4 (GA4)**: Use `@next/third-parties/google`
- **Google Tag Manager (GTM)**: Script in `<head>`, noscript after opening `<body>`

### b. Event Tracking

- **Page Views**: Automate page view tracking on route changes
- **Form Submissions**: Custom events for form submissions (e.g., `generate_lead` or `form_submit`)

## 4. Folder Structure & Architecture

### Folder Organization

- `@/components/ui`: Atomic, reusable UI elements (Buttons, Inputs, Modals)
- `@/components/layout`: Shared layout components (Navbar, Footer, Sidebar)
- `@/components/features`: Complex components grouped by features/modules
- `@/lib`: Configuration for external libraries or shared utilities
- `@/hooks`: Custom, reusable React hooks
- `@/types`: Centralized TypeScript interfaces and types
- `@/constants`: Global constants, enums, and configuration values
- `@/services`: Logic for API fetching and data transformations
- `@/data`: Static JSON files for JSON-LD and page content

### DRY Principle

- **Component Reusability**: Extract repetitive UI patterns into reusable components with flexible props
- **Shared Logic**: Move business logic into custom hooks or utility functions in `@/lib`
- **Centralized Config**: Store hardcoded strings, API endpoints, and config in `@/constants`
- **Type Safety**: Avoid duplicating type definitions; share via `@/types`

## 5. Coding Standards & Quality

- **Clean Structure**: Maintain established folder hierarchy
- **Styling**: Strictly use Tailwind CSS v4 design system
- **TypeScript**: No `any`. Use descriptive naming for variables and functions
- **Performance**: Optimize images, use Server Components by default, minimize client-side states
- **Lighthouse Scores**: Target SEO and Performance score of 90+

## 6. Code Generation Guidelines

When generating code:

1. Follow the established folder structure strictly
2. Use TypeScript with proper type definitions
3. Implement Server Components by default for pages
4. Include proper SEO metadata for pages
5. Use existing components from `@/components/ui` before creating new ones
6. Follow the DRY principle - extract reusable logic
7. Ensure proper heading hierarchy and semantic HTML
8. Optimize images with Next.js Image component

## 7. Testing & Validation

- Ensure Lighthouse SEO and Performance scores are 90+
- Validate heading hierarchy (H1 only once per page)
- Check metadata completeness (title, description, OG tags)
- Verify proper data structure implementation
